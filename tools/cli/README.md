# tools/cli — コマンド fd と、依頼文の解釈

`fd` は、AI（Claude Code）や人が呼ぶコマンドです。1 回呼ぶと 1 つの作業を最後まで行い、結果を JSON 1 個で出力して、実行ログ（`runs/<日付>/events.jsonl`）に追記します。`fd do "<依頼文>"` は、`nlq.py` が文をルールで読み、箱に入れる依頼なら `fd pick`、箱から取り出す依頼なら `fd take` と同じ処理を行います。読めない文と、素直な肯定の命令文でない文（「〜しないで」、質問、条件つきなど）は、何も動かさずに `need_llm` を返します。つかむ、取り出す、描くといった作業そのものは、各機能フォルダの関数に任せます。校正（`calib-at`、`calib-fit` など）、設定（`config`）、ログの集計（`report`）、実機のロック（`hw`）のコマンドは、`fd.py` の中に書いてあります。

| ファイル | 役割 |
|---|---|
| `fd.py` | 全部のコマンド。`COMMANDS`（名前と関数の表）と `build_parser()`（引数）。`main()` がカメラとアームを開き、関数を呼び、結果を出力してログに書く |
| `nlq.py` | 依頼文（日本語と英語）をルールで読む。`parse(text)` が、動作（`put_in` か `take_out`）と、対象と箱の条件を返す。単体で実行すると自己テスト |
| `fdtypes.py` | 認識 → 計画 → スキルの間で受け渡すデータ型（`SceneObject`、`Scene`、`GraspCandidate`、`ReleasePlan`） |

## 入口

- コマンドライン: リポジトリ直下の `./fd <コマンド>`。一覧は `./fd --help`、使い方は [docs/MANUAL.md](../../docs/MANUAL.md) の 1 章（道具と描画は 4 章、筆と絵の具・空中校正・爪・実機のロックは 11 章）にあります。
- コマンドは 6 種類です。1 回で作業を終えるもの（`do`、`pick`、`take`、`scene`、`ready`、`park`、`repl`）。1 動作ずつの低レベル（`state`、`torque`、`joints`、`tip`、`check`、`grip`、`grasp`、`probe`、`snap`）。道具と描画（`tool attach|status|set|rest|detach|calibrate|jaw`、`draw`、`track-test`）。筆と絵の具（`paint status|brush|check|look|locate|test|contact|preview|run|rinse|rest`）。実機のロック（`hw lock|unlock|status`）。校正と保守（`ref`、`calib-at`、`calib-fit`、`calib-roll`、`calib-air`、`table-fit`、`bench`、`selftest`、`config`、`camera`、`report`）。このほかに `gains`、`grasp-plan`、`servo-tip`（古い方式）があり、`home` は `ready` の別名です。
- **`paint`、`calib-air`、`tool jaw` の後ろの語は、`fd` では読まずに、そのままサブコマンドのモジュールへ渡します**（`paint/paintcli.py`、`calib/aircal_cli.py`、`draw/tooljaw.py` の `main(argv)`。先頭の `--` は 1 個だけ捨てます）。`fd --sim` のときは、渡す語の先頭に `--sim` を付けます。`fd calib-air --dry` や `fd paint --help` のように、最初の語がオプションでも通ります（2026-11-13 のレビューまでは、`fd` 自身のパーサーが「unrecognized arguments」で断っていました）。`--sim` は、ほかのコマンドと同じく、コマンドの**前**に書きます。この 3 つの後ろに書いた `--sim`（`fd paint --sim status`）は、`stage: options` で断り、`next` に正しい綴りを返します（そのまま渡すと、`fd` は実機のコマンドと記録したまま、中身だけがシミュレーションで動くためです）。`fd paint` のパーサーは、2026-11-14 から `--sim` というオプションを持たないので、`--si` のような省略形も断ります。この 3 つのサブコマンドのパーサーは、2026-11-14 朝から、オプションの省略形を受け付けません（`allow_abbrev=False`。`--scrap`、`--tip`、`--no`、`--sq` は `stage: options` で断ります）。`fd.py` 自身の `build_parser()` は、まだ省略形を受け付けます（`fd tool calibrate --pe` は `--pen`、`fd tool rest --over` は `--over-canvas`、`fd --si tool status` は `--sim` と読まれます）。後ろに書いた `--sim` を断るときの `next` のうち、`fd calib-air --sim` に対する `fd --sim calib-air` は、そのまま打つと断られます（シミュレーションにはカメラがなく、`--dry` か `--from` が要るため。`_sim_misplaced()`）。
- **絵の具用の道具とペンの区別**（2026-11-14 に追加。`fd.py` の `_painting_tool()`）: 道具のファイルに筆先を空中で測った記録（`tip_measured`）がある道具、可動爪の外側か爪の間に留めたという記録（`on_jaw` が `moving_outer` か `between`）や爪を保持した記録（`gripper_goal_raw`）がある道具と、絵のセットアップ（`paint_setup.json`）がある間のすべての道具は、絵の具用の道具です（`$FD_TOOL` で道具のファイルを指定したときは、`$FD_PAINT_SETUP` も指定したときだけ、セットアップを数えます）。固定爪に留めたという記録（`on_jaw` が `fixed`）だけでは、数えません（2026-11-14 朝に修正: 断った `fd ready` の `next` に従って `fd tool jaw mount fixed` と記録したペンが、絵の具用の道具になっていました）。絵の具用の道具には、`fd tool status`・`attach`・`set`、断った `fd draw`、`fd tip` / `fd joints` の `--contact` の `next` が `fd paint status` を言い、ペンの校正 `fd tool calibrate` は、`--pen` がなければ、アームもカメラも開く前に `stage: tool` で断ります。絵の具用の道具で、絵のセットアップがあるときは、`fd park`・`fd grip`・`fd pick` などを断る文と `fd torque off` の断りが、`fd tool rest` ではなく `fd paint rest` を挙げます（2026-11-14 朝に修正。`_fold_words()`。`--sim` の呼び出しには `fd --sim paint rest` と出ます）。
- **`fd --sim tool detach`**（2026-11-14 朝に修正。`_tool_detach()`）: シミュレーション用の道具のファイルがなく、実機の道具が登録されているとき（シミュレーションが実機の道具を映しているだけのとき）は、`attached: true`、`removed: false`、`mirrors`（実機の道具の名前）で、「何も外していない。グリッパーと `park` はロックされたまま」と答えます。
- **結果に出すコマンドの綴り**（2026-11-14 に修正）: `next`・`reason`・`notes` に出す `fd …` は、逆引用符 1 組につき、そのまま打てるコマンド 1 つです（縦棒で並べた綴りや `...` は出しません）。コマンドが値を知らない所は、逆引用符のない文で言います（2026-11-14 朝に修正: 「fd tool attach with --name and the tip registers it: …（`fd tool attach --help` lists the words)」「fd take --id N (N: its id in "scene")」など。`fd.py`、`tooling.py`、`tooljaw.py`、`paintcli.py`、`paintskill.py`、`aircal_cli.py`、`aircal.py` の文）。逆引用符の中に仮の名前が残っているのは、`draw/penskill.py` の 4 か所（`fd tool attach --name pen --along-fingers LEN`、`fd tool set --along-fingers LEN`、`fd draw NAME --dry` / `fd draw NAME`、名前だけの `fd draw`）と、`motion/robot.py` の 1 か所（`fd tool set --joint-limit wrist_flex=LO:HI`）です。`tests/test_cli_words.py` が、この 5 つを 1 つずつ名前を挙げて除いています。
- `fd.main(argv)`: コマンドラインと同じ処理です。テストはこれを呼びます。`fd.make_arm(sim)` は、実機のアームか、`--sim` のアームを作ります。
- `nlq.parse(text)`: `fd do` が呼びます（`fd repl` も `fd do` を通ります）。
- `fdtypes` の型: `vision/scene.py` が `Scene` と `SceneObject` を作り、`pick/grasp.py` が `GraspCandidate` と `ReleasePlan` を返します。
- 環境変数（テストと実験用）: `$FD_RUNS` は実行ログを書くフォルダ（既定はリポジトリの `runs/`）、`$FD_CONFIG` は設定、`$FD_CAMERA_MODEL` はカメラモデル、`$FD_TOOL` は道具のファイル、`$FD_PAINT_SETUP`・`$FD_PAINT_STATE`・`$FD_PAINT_OUT` は絵のセットアップ・状態・写真のフォルダ、`$TAZUNA_HW_LOCK` は実機のロックのファイル。`fd --sim` が覚えておくもの（シミュレーションの道具、紙、筆の状態）は、`fd.sim_state_dir()` が教える、木の外のフォルダに置きます。

## 必要なもの

- 読み込むフォルダ: 起動時に `motion` と `ik`。`pick`、`vision`、`draw`、`paint`、`calib`、`sim` は、そのコマンドが使うときだけ import します。`nlq.py` と `fdtypes.py` は、標準ライブラリだけで動きます。
- ハードウェア: サーボとカメラ。`--sim` を付けるとサーボを使いません。設定や校正のファイルを書き換えるコマンド（`config --set`、`calib-fit`、`calib-roll`、`table-fit`、`ref`）と `camera`、それに `hw lock` / `hw unlock` は、`--sim` を付けると断ります。`scene`、`pick`、`take`、`do` などは、保存した写真を `--frame` で渡すとカメラを開きません（アームを動かす `pick`、`take`、`do` では、`--frame` は `--sim` か `--dry` と一緒のときだけ使えます）。実機のロック（`fd hw lock`。`motion/hwlock.py`）が掛かっている間は、`--sim` を付けないコマンドは、サーボもカメラも開かずに `stage: hardware` で断ります。Python には numpy、OpenCV、feetech-servo-sdk、pyserial が要ります。

## テスト

`tests/test_cli_words.py`（28 件。2026-11-14 朝に 4 件: 固定爪に留めたペン、映しているだけのときの `fd --sim tool detach`、`fd paint rest` を挙げる断り方、`fd.py`・`tooling.py`・`tooljaw.py` の文字列の定数の綴り）が、`fd` がコマンドラインの語をどう扱うかを確かめます: `paint` / `calib-air` / `tool jaw` の後ろの語の渡し方と `--help`、後ろに書いた `--sim` の断り方と、どの使い方の表示にもその綴りが出ないこと、`fd tool set --joint-limit`（名前を挙げた関節だけを変える）、`fd tool status` の表示、道具が付いているときの `fd ready` の断り方、`fd tool rest` とキャンバス、絵の具用の道具と `fd tool calibrate --pen`、`fd --sim tool …` がシミュレーションの道具の写しについて言うこと、`fd` 自身の結果に出てくるコマンドの綴り。`tests/test_hwlock.py`（16 件）が、`fd hw lock|unlock|status` と、ロック中にサーボもカメラも開かないこと、ロックを知らないコピーの一覧（このフォルダの中の控えも）を確かめます（`fd` を別のプロセスで起動し、実行ログは `$FD_RUNS` のテスト用のフォルダに書かせます）。`nlq.py` は自己テストを持っていて（依頼文 157 例。MANUAL 8 章）、`tests/run_all.py` が最初に実行します。そのほかの `fd` のコマンドは、`tests/test_skills.py`（`pick`、`take`、`do`）、`test_tooling.py`、`test_tooljaw.py`（`tool jaw`）、`test_penskill.py`、`test_ink.py`（`snap`）、`test_tracking.py`（`track-test`）、`test_integration_pen.py`、`test_paint.py`（`paint`）、`test_aircal.py`（`calib-air`）が、`fd.main()` などを呼んで確かめます。`test_aircal.py`、`test_paint.py`、`test_cli_words.py`、`test_tooljaw.py` は、テストの間に結果に出てきた `fd …` のコマンドを集めて、`fd` とサブコマンドのパーサーに通します（結果に書いた綴りが、そのまま打てること）。

## 実機での状況

`fd do "…を箱に入れて"` と `fd pick` は、2026-11-11 に実機で動かしました。2026-11-13 には、筆を付けた状態で `fd tool attach / set / status / rest`、`fd snap`、`fd state` と、その日の時点の `fd paint look / locate / test / run / rinse / status` を実機で使い、`fd hw lock` で実機をロックしました。`fd take`、`fd tool calibrate`、`fd draw` と、2026-11-13 の夜に加えた `fd calib-air`、`fd tool jaw`、`fd paint brush / check / contact / preview / rest`、2026-11-14 未明と朝に加えた・直した断り方（絵の具用の道具への `fd tool calibrate`、`--pen`、`fd paint rest` を挙げる断り、オプションの省略形 ほか）は、シミュレーションと保存した写真でしか確かめていません（[PROGRESS.md](../../PROGRESS.md)）。実機を動かさずに試すには、`--sim`（シミュレーションのアーム）か `--dry`（計画だけ）を使います。
