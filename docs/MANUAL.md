## はじめに（このリポジトリを取り出して使う前に）

- **設定と校正は、作者の装置 1 組のものです。** `config/` の 4 つのファイル（`config.json`・`camera_model.json`・
  `calib_points.json`・`probes.json`）は、この SO-101（サーボの原点）、このカメラの置き場所、この机で測った値です。
  別のアームや別の配置では、測り直すまで、作業のコマンド（`do` / `pick` / `take` / `draw` など）を実機で実行しないで
  ください。試すときは `--sim`（シミュレーションのアーム）と `--dry`（計画だけ）にとどめてください。測り直しは
  [SETUP_SO101.md](SETUP_SO101.md) の順に、低速で行います。
  `config/config.json` が見つからないとき、または関節の原点・指先の位置・机の高さが入っていないときは、実機のアームを
  開きません（プログラムに入っている既定値は、そのアームで測った値ではないからです）。
- 開発機は Jetson Orin Nano Super（Linux、aarch64）で、Python 3.13、numpy 2.5、OpenCV 4.13、`feetech-servo-sdk` 1.0
  （`scservo_sdk`）、`pyserial` 3.5、`v4l2-ctl`（v4l-utils）を使っています。ほかの版では確かめていません。サーボは
  `/dev/ttyACM0`、カメラは `/dev/video0` です（`tools/motion/servo_bus.py` と `tools/vision/camera.py` の定数）。
- `fd` は `tools/cli/fd.py` を起動します。使う Python は、環境変数 `TAZUNA_PYTHON`、なければ `config/python` に書いたパス
  （1 行。その PC だけのファイルで、リポジトリには入れません）、どちらもなければ `python3` です。開発機では `config/python` に
  lerobot 環境の Python を書いてあります。文書中の `/home/jetson/…` は開発機のパスです。
- テストは実機なしで動きます（8 章）。`python tests/run_all.py` で全部、`python tests/test_ink.py` のように 1 本ずつでも
  実行できます。
- `CLAUDE.md` は、この装置を Claude Code から操作するための手順書です。リポジトリを Claude Code で開くと、指示として
  読み込まれます。

## 1. 使い方（これだけ）

```bash
cd ~/lerobot/tazuna
./fd do "青いキューブを箱に入れて"     # 見る → 計画 → つかむ → 箱に入れる → 確認 まで 1 回で
./fd do "箱の中の白いキャップを取り出して"  # 箱の中の物を取り出して机の空いた場所に置く（これも 1 回）
./fd park                              # 終わったら収納（トルク OFF・カメラを自動露出に戻す）
```

| コマンド | 何をするか |
|---|---|
| `./fd do "<依頼文>"` | 日本語／英語の「◯◯を箱に入れて」「箱の中の◯◯を取り出して」をルールで解釈して実行（LLM 不要）。結果の `say` が日本語 1 文の報告。実行するのは素直な肯定の命令文だけで、「〜しないで」・条件・質問などは動かさずに `need_llm` を返す（2 章） |
| `./fd pick --color blue` | 色・形（`--kind box\|cylinder`）・番号（`--id N`）で対象を指定して実行。`--all` で該当する物を全部 |
| `./fd pick ... --dry` | 計画だけ（何も動かない）。どうつかむかを確認できる |
| `./fd take --color white --hollow` | **箱の中の物を取り出して机に置く**。`--id N`、`--from-color black`／`--from-id M`（どの箱から）、`--to x,y`（置き場所。省略時は最寄りの空き）、`--hollow`（キャップ・コップなど上が開いた中空の物: 壁をつまんでよい）／`--solid`、`--dry` |
| `./fd scene` | テーブルの上の物体一覧（id・色・形・寸法・位置、箱の中の物） |
| `./fd repl` | 対話モード。依頼文を 1 行ずつ打つだけ。カメラと通信を開いたままなので起動待ちも LLM 推論もゼロ |
| `./fd ready` / `./fd park` | 待機姿勢（トルク ON）／収納姿勢（トルク OFF）。道具（ペン）が登録されている間は、`ready` は道具の先端を待機点に置き、`park` は断る（片付けは `./fd tool rest`） |
| `./fd tool …` / `./fd draw 絵` | グリッパーに留めた道具（ペン）の登録・校正・片付けと、線画の描画（4 章。**実機では未検証**）。道具が登録されている間は `pick` / `take` / `do` / `repl` / `park` などを動く前に断る |
| `./fd --sim <コマンド>` | シミュレーションのアームで実行（サーボには一切触れない）。**カメラは実物を使う**（`--frame` なしだと実カメラを開いて焦点・露出・ホワイトバランスを固定し、撮影する。固定は実機の `park` か `./fd camera auto` まで残る。`./fd --sim park` はカメラの設定に触れない）。`--frame 画像` を付けると保存画像を使い、ハードウェアに一切触れない。`--frame` は `--sim` か `--dry` と一緒のときだけ使える（`pick` / `take` / `do` / `repl` で実機を保存画像から動かす指定は、何も開く前に拒否）。`./fd --sim tool …` / `track-test` / `draw` は紙とカメラもシミュレーションで、実カメラを開かない（4 章） |
| `./fd bench --tier T [--accept]` | 速度段 T の実機ベンチマーク（合格したら `--accept` で使用可能にする） |
| `./fd selftest` | 読み取りだけの自己診断（通信・校正値・カメラ・認識）。何も動かない |
| `./fd state` | 関節角・手先位置・温度・電圧・負荷など |
| `./fd report` | 今日の実行ログの集計（1 個あたりの時間を段階別・速度段別に、失敗理由、ベンチ結果）。調整の材料に |

`pick` / `take` / `do` が失敗したときは、結果 JSON の `stage`（どの段階か）・`reason`（理由）・`arm_state`
（アームの状態）・`next`（次の一手）を見れば足ります。低レベルコマンド（`tip`, `joints`, `grip`, `grasp`,
`probe`, `snap` など。`./fd --help` 参照）は復旧用です。

### 箱から取り出す（`fd take`）

```bash
./fd take --color white --hollow        # 箱の中の白いキャップを取り出して、机の最寄りの空いた場所に置く
./fd take --id 4 --to 0.23,-0.03 --dry  # 番号で指定・置き場所を指定・計画だけ
```

キャップやコップ（上が開いた中空の物）には `--hollow` を付けます。`fd do` の依頼文で「キャップ」「ふた」「コップ」
「カップ」（cap / lid / cup）と呼べば付けたのと同じです（理由は下の「つかみ方」）。

1 回の呼び出しで次を順に行い、どこかの確認に落ちたらそこで止まって理由を返します（`stage`）:

| 段階 | 内容 |
|---|---|
| `perceive` | 箱と、その**中**の対象を見つける。アームが箱の一部を隠しているときは、いったん畳んで見直す |
| `plan` | 対象のまわりの空きから、つかみ方と爪の向きを決める（下記）。置き場所も決め、全経路を事前検査 |
| `approach` → `visual` | 箱の縁より 12 mm 上で止まり、**爪をカメラで見て**（`detect_jaws`）位置のずれを測り、その分だけ降下位置を直す。**測れなければ降りずに待機姿勢へ戻る**（取り出しでは必須。設定でも切れない）。測定値が 12 mm を超える・検出窓の端にある・次の目視と合わない（補正が確認できない）ときも降りない。測れるものの限界は下の「爪の目視で分かること・分からないこと」 |
| `descend` | 目視で直した位置をまっすぐ降下。**高さは幾何だけで決める**: 机の高さ（`table_z`）＋箱の底の厚み＋物自身の底の厚み。壁をつまむときは空洞の内底の 2 mm 上で閉じる。触って測らない（下の「高さ」） |
| `grasp` → `lift` | 閉じる → 12 mm 持ち上げて爪の位置と負荷で保持を確認 → 物の底が縁より 25 mm 上になるまで真上へ → カメラで「元の場所から消えた」ことを確認 |
| `transfer` → `release` | 箱の外へ運び、机の空いた場所に下ろして開く。待機姿勢へ |
| `verify` | カメラで「机の上にある」「箱の中にない」を確認。隣の似た色の物（白とアイボリー）を取り違えたとき＝机の上の物の色名が対象と違う、または対象が元の場所に 2 回（持ち上げ時と最後）見えたままのときは確認しない。取り違えと分かれば `reason` が「the wrong object was taken out …」になり、`next` に次の一手が入る |

つかみ方は 2 通りです（`takeout.py`）。**中空で上が開いた物（キャップ、コップ）は壁をつまめます**: 固定爪を壁の外、
可動爪を空洞の中に入れて壁を挟む（11/11 に手動で成功した方法）。それ以外は対象を両側から挟む通常の把持で、
両方の爪に空きが要ります。どの向きにするかは空きで決めます: 向きごとに、対象の外面から箱の壁や隣の物までの
空き距離を爪の幅（12.7 mm）の帯で測り、**その障害物の上端の高さでの爪の厚み**（固定爪の背は先端で 5.2 mm、
10 mm 上で 8.8 mm、20 mm 上で 12.5 mm）＋対象との隙間＋余裕と比べます。爪先の 1 点ではなく爪の輪郭で判定するので、
11/11 のように爪の背が壁に当たって箱を回すことを計画段階で避けられます。どの向きにも空きがなければ `plan` で止まり、
何が邪魔かと「先にどれを取り出すか」を `next` に返します。

**壁つまみは「中空で上が開いている」と言われた物にだけ使います。** 言う方法は 3 つ: カメラの認識（場面の `hollow` 欄。
縁の内側に内壁と内底が見えたとき `true`）、`--hollow`、依頼文の言葉（`fd do` で「キャップ」「ふた」「コップ」「カップ」）。誰も何も
言っていない円柱は、両側から挟める空きがあればそうし、なければ `plan` で止まって `next` に次の一手を 2 通り返します
（キャップなら `fd take --id N --hollow`、中実なら先にどれを取り出すか）。降りる前に空洞を確かめる手段がなく、
中実の円柱を中空と思い込むと可動爪がその上面に降りて押してしまうためです。カメラが「上は閉じている」
（`hollow: false`）と言った物は、依頼文が「キャップ」でも壁をつまみません（`--hollow` はそれより優先）。

**高さ**: 把持の高さは場面の幾何から決め、触って測りません。`Arm.probe_down` は指先が面に触れても腕が止まらず、
最初の接触より 3〜18 mm 深い値を返すことが 11/11 に分かったためです（統合担当がカメラで 9 か所計測。押し込むと
指先は 1 mm あたり 1.0〜1.5 mm 外へ滑り、触れた物を動かす）。11/11 のキャップは指先が内底の 3 mm 下（押し付け）から
7 mm 上のどこにあっても保持できたので、内底の見込みの 2 mm 上を狙えば上下に 5 mm ずつ余裕があります。
`--probe on`（`auto`: 把持の余裕が 3 mm 未満のとき）は任意の**確認**で、最後の降下の前に開いた爪を「予定の高さの
2 mm 先」までゆっくり下ろし、それより上で何かに当たったら止まります（裏返しのキャップ、中に入っている物）。
当たらなければ何も変わらず、**把持の高さを変えることはありません**。既定は `off` です。

**爪の目視で分かること・分からないこと**（11/11 夜のレビューで判明）: 目視が測るのは、縁より上の位置で「カメラに
写った爪」と「関節角から計算した爪」がどれだけずれているか、だけです。

- **測れる範囲**: 検出器は計算上の位置のまわり 36 画素しか探しません。机の上の距離にすると、カメラから見て
  **左右に約 ±10 mm、奥行き（視線方向）に約 ±18 mm**（場所により 15〜20 mm）。これより大きいずれは「窓の端」に
  見えるだけです。
- **測れないもの**: カメラの視線に沿ったずれは画像に現れません。腕の高さの誤差は、奥行き方向のずれとして
  約 1.2〜1.5 倍に見えます（区別できません）。対象の位置そのもの（画像から換算した机上の座標）の誤差も測りません。
- **11/11 午後のずれは捉えられていなかった**: 爪が実際にキャップの壁を挟んだ 2 回（14:34、14:36）について、
  記録から「カメラが見たキャップの位置」と「腕がいた位置」を比べると、当時の校正で 11.9 mm と 16.2 mm
  （ほぼ視線方向）、16 時に直した校正でも 6.4 mm と 6.4 mm 離れていました。同じ時間帯の 4 枚の写真で目視が
  読んだ値は 3.6〜6.5 mm（直した校正では 2.7〜4.7 mm）で、その分を補正しても足りていません。
- **つまみが許すずれ**: 壁つまみは、顎の閉じる方向に対象側へ 6 mm ずれると固定爪が、反対側へ 8 mm または
  横へ 7 mm ずれると可動爪がキャップの壁の上に降ります（爪の実形状での検査）。余裕はおよそ 5 mm です。
- **そのため**: 受け入れる補正は 12 mm まで（`take.max_visual_corr`。左右は窓の端 = 約 9 mm が先に効きます）。
  測定値が 12 mm を超える、窓の端（探す範囲の 90 % より外）にある、次の目視と 4 mm を超えて食い違う、最後の
  補正を次の目視で確かめられなかった、のどれでも降りずに `visual` で止まります（理由に「calibration?」等）。
  それでも視線方向のずれは見逃すので、**実機の初回は空つかみが起こり得ます**（空つかみ・持ち上げ時の滑り・
  取り違えは検出して止まります）。校正を変えたら 5 章の「カメラと腕の一致」の確認を先に行ってください。

`arm_state` の意味: `parked` 収納（トルク OFF）／ `ready` 待機姿勢／ `standby` 箱の真上で待機（次の依頼がいちばん速い）／
`stopped` 途中で停止して保持中／ `holding_object` 物体をつかんだまま停止。
`ready` `standby` `stopped` `holding_object` は **トルク ON のまま** です。離席するときは `./fd park`。

## 2. 推論の待ち時間を減らす仕組み

1. **依頼 1 件 = コマンド 1 回**（`skills.py`）。認識・把持計画・全経路の事前検査・動作・各段階の数値チェック・
   カメラでの最終確認までを 1 プロセスで行います。LLM が要るのは「どれを運ぶか曖昧なとき」と「チェックに落ちたとき」だけ。
2. **依頼文はルールで読む**（`nlq.py`、`fd do`）。「青いキューブを箱に入れて」「箱に白いキャップを入れて」
   「赤と青のブロックを箱に入れて」「ブロックを全部箱に片付けて」などは LLM の判断なしでそのまま実行。取り出しの依頼
   （「箱の中の白いキャップを取り出して」「白いキャップを箱から出して」「箱から赤いブロックを取って机に置いて」）も
   同じく読んで `take` を実行します（「キャップ」「ふた」「コップ」「カップ」と呼ばれた物は、壁をつまんでよい中空の物として
   扱います）。読めない文・曖昧な文は **推測せず** `need_llm` を返し、そのとき見えている
   物体一覧も一緒に返すので、次の 1 回（`fd pick --id N`／`fd take --id N`）で済みます。
   **実行するのは素直な肯定の命令文だけです。** ルールは「どの物・どの箱か」を拾うだけで文の意味は分からないので、
   禁止（「取り出さないで」「入れるな」"don't …"）、除外（「白いキャップ以外」）、否定（「白くないキャップ」）、
   条件・順序（「〜たら」「〜てから」"if …"）、選択（「赤か青」）、質問、過去形や平叙文（「取り出した」）、
   2 つ目の指示や場所の指定が付いた文（「取り出してから戻して」「取り出して机の右に置いて」"… and then put it
   back"）、箱が 2 つ出てくる文（「赤い箱から白い箱に…」）は、**物と箱の名前が読めても実行せず** `need_llm` を
   返します（何が見つかったかは `not_plain` に入ります）。11/11 夕方までは「箱の中の白いキャップを取り出さないで」を
   取り出しとして実行していました。
3. **`fd repl`**: 端末で依頼文を打つだけ。LLM を一切通さないので推論待ちゼロ、プロセス起動・カメラ起動の待ちもゼロ。
4. **出力は短い JSON + 日本語 1 文（`say`）**。LLM が読む量が少なく、報告は `say` をそのまま伝えれば終わり。
   画像は失敗時に必要なら見る（パスは `images` に入る）。事前・事後の撮影確認は不要です。
5. **失敗時は `next` に次の一手**を 1 行で返すので、LLM が状況を調べ直す往復が減ります。
6. **オペレーター手順書 [CLAUDE.md](../CLAUDE.md)**: 新しいセッションでも、ソースを読み直さず最短でコマンドを呼べます。
7. セッション側のコツ: 定型の運搬だけなら推論の深さ（effort）を下げる・`/fast` を使う・小さいモデルに任せる、でも
   十分動きます（判断はハーネス側が数値で行うため）。

### 定型外の作業: 時間を失わないために

11/11 午後の取り出しは、低レベルコマンド 92 回・42 分で、ロボットが動いていたのは 4 分でした（残り 38 分は
コマンドの間の LLM の推論）。同じ作業は `fd take` 1 回（シミュレーションで、待機姿勢からなら 14〜17 秒、収納姿勢から始めると約 21 秒）です。定型外の依頼でも:

1. **まず 1 コマンドで済まないか確かめる**（`fd do "<依頼文>"`、`fd take`、`fd pick`、まず `--dry`）。
   手動の手順を組み立てるのは、それが理由つきで断られてから。断られたときは結果の `next` に次の一手があります。
2. **画像を見て考え込まない**。判断に使う数値は結果 JSON の `checks` にあります。画像は失敗したときに
   `images` の 1 枚だけ。事前・途中・事後の確認撮影を挟むと、1 枚ごとに推論の往復が増えます。
3. **細かい把持の高さは計算で決める。触って測った値は使わない**。机の高さ（`table_z`）＋箱の底の厚み＋物の底の
   厚みで足ります。`fd probe` は指先が触れても腕が止まらないので、最初の接触より 3〜18 mm 深い値を返し、押し込んだ
   分だけ指先が外へ滑って触れた物を動かします（11/11 に統合担当が実測。同じ日に高さが約 1 cm 合わなかったのは
   腕の原点のずれが原因で、本番ツリーの校正は 16 時に直してあります）。`probe` を使うのは「そこに何かあるか」を
   確かめるときだけにし、面の 2 mm より先へ押し込まない（`take` の `--probe on` はそうしています）。
4. **位置は、爪と対象を同じ 1 枚の写真で見比べて合わせる**。箱の縁より上で止めて
   `fd snap --crop x0,y0,x1,y1 --scale 4 --plain` を 1 枚。画像から換算した座標をそのまま信じて降ろさない
   （`take` は `detect_jaws` で自動的に測って補正し、測れなければ降りません。ただしこの自動の目視には
   測れないずれがあります: 1 章「爪の目視で分かること・分からないこと」）。
5. 箱の中へ手動で降ろすときは爪の厚みを忘れない: 固定爪の背は上ほど厚く（先端 5.2 mm、20 mm 上で 12.5 mm）、
   幅は 12.7 mm。壁との隙間が約 18 mm 未満の場所に固定爪を降ろすと、壁を押して箱ごと回します。薄い壁は
   `fd grasp --thin` で挟み、1 cm 持ち上げて `fd state` の爪の値を見る（保持: 閉じたときの位置のまま・負荷約 160。
   抜けた: 位置が目標側へ寄り、負荷約 80）。

## 3. 動作そのものの高速化

| 項目 | v1（11/10 実測） | v2 |
|---|---|---|
| 1 個あたりの LLM 呼び出し | 23〜28 回（思考 160〜310 秒） | 1 回（`fd do`）／0 回（`fd repl`） |
| 認識 + 把持計画 | 約 22〜24 秒（箱の当てはめ 10 秒超 + 把持計画 12〜14 秒） | 0.2〜0.5 秒 |
| カメラ 1 枚 | 約 1.2 秒（毎回デバイスを開く） | 常駐スレッド（起動後は数十 ms） |
| ロボットの動作時間（1 個） | 約 105〜115 秒 | 下表（シミュレーション） |
| 合計（1 個） | 267〜424 秒 | 低速段でおよそ 20〜25 秒 + LLM 1 呼び出し |

ロボット動作時間の見込み（**シミュレーション**、作業範囲のランダムな配置での平均。箱の上の待機からの 1 個。
収納姿勢からの初回は +6 秒前後）と、11/11 の実機ベンチの結果:

| 速度段 | 移動の最高関節速度 | 速度の付け方 | 1 個あたり（見込み） | 実機ベンチ（11/11） |
|---|---|---|---|---|
| `slow` | 25 °/s | なめらか（中央で最高速） | 約 20 秒（実測 17.6 秒 + 確認） | **合格**: 追従誤差 最大 5.3°、最低電圧 4.0 V |
| `slow_cruise`（既定） | 25 °/s | 巡航（加速→一定→減速） | 約 14 秒（実測: 収納姿勢から 21.7 秒。確認の見直し 4 秒を含む） | **合格**: 5.2°、4.1 V（低速と同じ余裕） |
| `normal` | 45 °/s | なめらか | 約 14 秒 | **合格**（3 回目）: 6.0°、3.8 V。余裕は薄い |
| `normal_cruise` | 45 °/s | 巡航 | 約 10 秒 | 未実施（電圧の落ち込みが心配なので見送り） |
| `fast` / `fast_cruise` | 70 °/s | なめらか／巡航 | 約 8 秒 | 未実施（同上） |

どの速度段でも、物体への接近（12 °/s）と精密動作（8 °/s）は低速のままです。中速で接近を 20 °/s にしたところ、
降下後の位置誤差が 0.86°（手先で約 4 mm）残ったためです。また中速以上では手首ロールを 40 °/s に抑えています
（54 °/s では追従誤差が 7.7° に達しました）。速度の実質的な上限は **5 V 電源の落ち込み** です。

実機ベンチに合格していない速度段は **コードが拒否します**。`./fd bench --tier T --accept` が実機で合格した段だけ
使えるようになり、`--make-default` を付けると既定になります（5 章）。いま使えるのは `slow` `slow_cruise` `normal` です
（例: `./fd do "..." --tier normal`）。既定は `slow_cruise` です（11/11 に実ピックが成功したので `slow` から切り替えました。
戻すには `./fd config --set 'speed_tier="slow"'`）。

速くした中身:

- **経路をつなげて止まらない**: 「持ち上げ → 横移動 → 下ろす」を 1 本の動作に。グリッパは移動中に開閉。
  静止待ち（セトリング）は必要な所だけ・収まり次第すぐ次へ。
- **一発把持**（`grasp_fast`）: 段階的に閉じる方式（約 1.8〜2.3 秒）をやめ、1 回で閉じて止まった位置で判定（約 0.5 秒）。
- **箱の真上で待機**: 入れ終わったら遠い待機姿勢まで戻らず、箱の上に上がって待ちます（次の物体へ直行）。
- **手首ロールを回し戻さない／ロールだけ 1.6 倍速**: 測ってみると移動時間の多くが手首の回転でした。
  ロールは重力負荷がなく、11/10 に 40 °/s での動作実績があります。
- **把持計画は閉形式**（総当たり探索をやめた）、**認識は縮小画像 + 幾何モデル**で 0.1〜0.35 秒。
- **動く前に全経路を検査**: 逆運動学・関節限界・床・立入禁止領域・角の丸め込みまで、実行時と同じ検査を先に済ませるので、
  途中で止まって LLM に相談する場面が減ります。

取り出し（`fd take`）1 個の所要時間（**シミュレーションのみ**。既定の `slow_cruise`、`test_skills.py -v` の実測値）:

| 場面 | ロボット時間 | 内訳 |
|---|---|---|
| 待機姿勢から、キャップの壁をつまんで取り出す | 約 14 秒 | 接近 2.3 / 降下 1.9 / 閉じる 0.6 / 持ち上げ 2.3 / 運搬 3.1 / 開いて待機姿勢へ 3.2 |
| 同上 + 爪の目視で 5 mm 補正（閉じて見直し 1 回を含む） | 約 16 秒 | 目視 1.2 秒（カメラ待ちは含まない） |
| 保存画像の場面（実際の認識、置き場所を指定） | 約 17 秒 | 接近 4.0 / 開いて待機姿勢へ 4.2 |
| 箱がアームの陰で、畳んで見直した場合 | 約 21 秒 | 見直し 3.7 秒 + 展開 3.8 秒 |
| 通常の両側把持、収納姿勢から | 約 17 秒 | 展開を含む接近 6.1 |
| 任意の接触確認（`--probe on`）を付けた場合 | 約 19 秒 | 接触確認 5.4 秒 |

収納姿勢から始めると展開で約 +3.8 秒です。実機ではこれに、爪の目視（1〜3 秒）、`pinch` の待ち（約 +1 秒）、
最終確認（約 0.5 秒）が加わる見込みで、目標の 40 秒に対して 20 秒前後と見ています（未実測）。

## 4. 道具（ペン）と描画

> **この章の機能は、実機では一度も動かしていません**（2026-11-12 未明に追加）。確かめたのは、シミュレーションのアームと紙、
> それに 11/11 夜の保存写真だけです。この章で「シミュレーション」と書いた数値は、実機の実測ではありません。
> 実機の初回は 5 章「朝の実機確認（道具と描画）」の順に、見ている状態で行ってください。

11/11 の夜、グリッパーにペンをテープで留めて猫を 1 枚描きました。そのときハーネスにはペンの機能がなく、その場で作った
スクリプト（`tools/prototypes/pen_draw/`）で 75 分かかりました。写真に写っていないだけの線を「書けていない」と判定して押し込み続け、
紙に試し線を 8 か所重ね書きしています。そのとき分かったことを `fd` に組み込んだのがこの章です。

```bash
cd ~/lerobot/tazuna
./fd tool attach --name pen --along-fingers 0.055   # ペンを登録する（指先からペン先まで 5.5 cm）
./fd tool calibrate                                 # 紙の上でペンを測る（先端 → 接触高さ → 位置補正 → 線の向き）
./fd draw cat --dry                                 # 配置とプレビュー画像だけ（何も動かない）
./fd draw cat                                       # 描く → 最後に写真で線を確認
./fd tool rest                                      # 片付け（ペンを付けたまま収納。park は使えない）
```

### 道具とは

- **道具 = グリッパーにテープで留めた物**（ペンなど）です。ハーネスは「道具のファイル」1 個（`tool_active.json`。
  プロジェクトのフォルダ直下）でそれを知ります。ファイルがなければ「道具なし」で、これまでと全く同じ動きです。
- **登録していない道具は、ハーネスには見えません。** ペンが付いたまま `fd park` を実行すると、グリッパーを開いて腕を畳み、
  ペン先を机に押し込みます（11/11 のペンなら、計算上、机の面より約 1.5 cm 下まで）。ペンを付けたら最初に
  `fd tool attach`、外したあとに `fd tool detach` です。
- 道具が付いている間、**「先端」は指先ではなく道具の先端**です。経路の計画も、「机より下へ行かない」「立入禁止領域に
  入らない」の検査も道具の先端で行い、道具の胴体（指先から先端まで）も検査します。
- **グリッパーには一切指令を出しません**（開閉するとテープが外れます）。次のコマンドは、動く前に断ります:
  `pick` `take` `do` `repl` `grip` `grasp` `probe` `bench` `park` `calib-at` `servo-tip`、それに `tip` / `joints` の
  `--contact`（机の高さより下へ押し込む指定）。断るときの `next` は `fd tool rest` と `fd tool detach` を案内します。
- `fd ready` は、道具の先端を待機点（机の 12 cm 上）に置きます。`fd park` の代わりは `fd tool rest` です。
  `fd torque off` は、道具の収納姿勢のときだけ通ります（ほかの姿勢では腕が落ちて道具が机に当たるため）。
- 道具を付けたままの空中の移動（`ready`、`tool rest`、紙の横への移動）は、**先端が机の 2 cm より下に来ない**経路だけを
  通ります。先端が低い（3.5 cm 未満）ときは、まず真上へ持ち上げます。動いている間も、関節の角度から計算した先端の
  高さが 2 cm を切ったら止まります。

### コマンド

| コマンド | 何をするか | アームは動くか |
|---|---|---|
| `./fd tool attach …` | 道具を登録する。以後グリッパーはロック | 動かない（読むだけ） |
| `./fd tool status` | 何が付いているか、校正済みか、次の一手 | 動かない（ファイルを読むだけ。アームの電源が切れていても使える） |
| `./fd tool set …` | 登録内容を直す | 動かない |
| `./fd tool calibrate` | 紙の上で道具を測る。`fd draw` の前に必要 | **動く。ペンが紙に触れる** |
| `./fd tool rest` | 道具を付けたまま収納してトルク OFF | 動く |
| `./fd tool detach` | 登録を外す（道具を実際に外してから） | 動かない |
| `./fd snap --exposure paper` | 白い紙用の露出で 1 枚撮る（線が写る） | 動かない |
| `./fd track-test` | 空中で図形をなぞり、先端が計画にどれだけ付いていくかを測る | 動く（紙には触れない） |
| `./fd draw 絵` | 線画を描く（1 回で写真 → 配置 → 描画 → 確認まで） | **動く。ペンが紙に触れる** |

どのコマンドも結果は JSON 1 個で、`ok` / `stage`（どこまで進んだか）/ `reason` / `next`（次の一手）と日本語の `say` が
入ります。`--dry` があるコマンドは、付けると計画だけで、何も動きません。

#### `fd tool attach`（登録する）

```bash
./fd tool attach --name pen --along-fingers 0.055
```

| オプション | 意味 |
|---|---|
| `--name N` | 道具の名前（必須） |
| `--along-fingers LEN` | 指に沿って留めた、まっすぐな道具。LEN は指先から道具の先端までの長さ（m） |
| `--across-fingers LEN` | 指と直角に、固定爪の側へ突き出して留めた道具 |
| `--tip x,y,z` | 先端の位置を直接指定（グリッパーの座標、m。x: 固定爪の向き、y: 横、z: 指に沿う向き） |
| `--pitch P` | その道具で作業するときのグリッパーの傾き（度。既定: 指に沿う道具 75、直角の道具 30） |
| `--replace` | 登録済みの道具を置き換える（校正は消える）。付け直したとき・ずれたとき |
| `--mount along_fingers\|across_fingers\|other` | 留め方を明示する（ふつうは不要。上のオプションから決まる） |
| `--note 文` / `--no-robot` / `--dry` | メモを残す／アームを読まない（電源が切れている・テレオペ中）／内容の確認だけ |

返ってくるもの: `tool`（名前、先端 `tip_offset`、長さ `length_mm`、傾き、校正の有無）、`arm`（いまの姿勢での道具の先端の
高さ `tip_height_mm`、道具を付けたままの収納姿勢 `rest` と待機姿勢 `standby` が作れるか）、`locked`（断られるコマンド）、
`file`、`say`（例:「ツール「pen」を登録しました（先端はグリッパーから 55 mm）。グリッパーはロックされ、park の代わりに
fd tool rest を使います。」）。アームは読むだけで、動きません。

**長さは定規で、5 mm 以内を目安に測ってください。** 校正が最初に探すのは、「紙があるはずの高さ」の 12 mm 上から
6 mm 下までです。実際より 6 mm ほど長く登録すると、紙に届かないまま探索が終わります（何も書かれません）。
実際より 12 mm 以上短く登録すると、空中のはずの 1 本目から紙を押します（シミュレーション: 15 mm 短く登録したとき、
最初の 4 本で紙の面の 7 mm 下まで押す指令になりました）。`arm.tip_height_mm` を実物と比べれば、動かす前に気づけます。

#### `fd tool status`（確かめる）

```bash
./fd tool status
```

返ってくるもの: `attached`（付いているか）、`tool`（上と同じ内容に、測った接触高さ `contact` と位置補正 `corr_map` の
品質の数値）、`locked`、`next`、`say`（例:「ツール「pen」が付いています（未校正: tip, contact, map）。描く前に
fd tool calibrate が必要です。」）。

#### `fd tool set`（登録内容を直す）

```bash
./fd tool set --along-fingers 0.060      # 長さを測り直した
```

オプションは `attach` と同じ（`--replace` はなし。`--name` は任意）に加えて、`--region x0,y0,x1,y1|none`（校正が有効な
範囲の記録）と `--keep-calibration`。返ってくるもの: `changed`（変わった項目）、`calibration_dropped`、`before` / `tool`、`say`。
**先端・留め方・傾きを変えると、測った接触高さと位置補正は捨てます**（`calibration_dropped: true`）。
`--keep-calibration` を付けると記録は残りますが、先端が 0.5 mm、傾きが 0.5° より大きく変わっていれば、`fd draw` は
その校正を使わずに `tool` の段階で断ります（11/12 朝に修正。それより小さい直しなら、そのまま描けます）。

#### `fd tool calibrate`（紙の上で測る）

```bash
./fd tool calibrate                    # 4 段階を順に全部
./fd tool calibrate --stage contact    # 1 段階だけやり直す
```

| 段階 | 何を測るか | 紙に書く物 | 成立しないとき |
|---|---|---|---|
| `tip`（先端） | ペン先の本当の位置。最初にインクが出た線の高さ（長さの誤差）と場所（横・前後の誤差）から、登録値を直す | 「はしご」1 か所。枠の左（ロボットから見て右）の外 | インクが出ない／直す量が 30 mm を超える |
| `contact`（接触高さ） | 紙に触れ始める高さを 4 か所で測り、平面にする | はしご 4 か所。枠の左右の外 | 3 か所未満／平面からのばらつき（RMS）が 1.5 mm 超／傾きが 10 cm あたり 6 mm 超 |
| `map`（位置補正） | 狙った場所と、実際にインクが付いた場所のずれ。印から補正の式（一次式）を作る | 3 mm の短い線 8 個。枠のまわり | 見つかった印が 6 個未満／式とのずれ（RMS）が 3 mm 超 |
| `direction`（線の向き） | ロボットから遠ざかる向き・近づく向き・横向きで、線の欠け方が違うか | 20 mm の線 6 本。枠の右（ロボットから見て左）の外 | 写真で線の有無を判定できない |

「はしご」は、6 mm の短い線を 4 本、1 本ごとに 1.5 mm 低くして書く物です（下の「下ろし方の決まり」）。「枠」は、あとで
`fd draw` が描く場所（既定 105 mm 四方）で、試し書きはその外に、古い線から 3 cm 離して置きます（印と向きテストは、
場所がなければ 1.5 cm まで近づけ、結果にそう書きます）。

| オプション | 既定 | 意味 |
|---|---|---|
| `--stage tip\|contact\|map\|direction\|all` | `all` | 1 段階だけ、または全部（この順） |
| `--dry` | — | 写真 1 枚と計画だけ（試し書きのおおよその場所とプレビュー画像）。何も動かない |
| `--size MM` | 105 | あとで描く枠の大きさ。試し書きはこの枠を避ける |
| `--at x,y` | 紙のうちペンが届く範囲の真ん中 | 枠の中心（机の座標、m） |
| `--marks-on outside\|scrap` | `outside` | `outside`: 試し書きは枠の外。`scrap`: 枠の中にも書く（捨てる紙のとき） |
| `--places N` | 4 | 接触高さを測る場所の数（3〜8） |
| `--start-above MM` | 12 | 最初の探索を、紙があるはずの高さの何 mm 上から始めるか。20 までにしてください（1 回の探索ははしご 5 本までで、25 を超えると紙まで届かないことがあります。そのときも理由は「6 mm 下まで探した」と出ます） |
| `--truth FILE` / `--new-sheet` | — | シミュレーション専用（下の「シミュレーションでの予行」） |

返ってくるもの: `stages`（段階ごとの結果。はしごごとの高さ `plan_z_mm` と線の有無 `inked`、先端を直した量 `shift_mm`、
平面のばらつき `rms_mm`、印ごとの位置、向きごとの欠け `missing`）、`box`（あとで描く枠）、`photos`（撮った写真。
`runs/<日付>/` の中）、`calibrated`（tip / contact / map が済んだか）、`pen`（終わったときのペン先の高さとアームの状態）、
`say`。シミュレーションでの `say` の例:

> ツール「pen」の校正（tip・contact・map・direction）が終わりました。先端位置を 15.8 mm 修正、接触高さ 4 か所
> （平面からのずれ RMS 0.38 mm）、位置補正 印 8 個（RMS 1.22 mm）、線の向き: 向きによる差なし。ペン先は机の 79 mm 上、
> アームは紙の横の待機姿勢（トルクON）です。（シミュレーションです。実機の結果ではありません。）

- 最初に、腕を紙の横へどけて写真を撮ります（トルク ON になり、腕が動きます）。写真が線を写せなければ、ペンを下ろす前に
  止まります。
- 各段階は道具のファイルを読み書きするので、1 段階だけやり直せます。`tip` をやり直すと、接触高さと位置補正は消えます
  （先端が変わるので測り直し）。`map` には `contact` が、`direction` には `contact` と `map` が先に必要です。
- 全部まとめて実行したとき、最後の `direction` だけ紙の空きがなくてできなかった場合は、校正は成立とし、結果の `notes` に
  「向きテストは未実施」と書きます。
- 試し書きは枠の外を狙いますが、位置補正ができる前は、インクが狙いから 2 cm 近くずれて付くことがあります（11/11 の実測で
  最大 16.6 mm）。枠のすぐ外の印が枠の中に入っていないかは、写真で確かめてください。
- シミュレーションでは 4 段階で約 5 分（ロボットの動作時間）、写真 19 枚でした。実機では測っていません。

#### `fd tool rest`（片付ける）

```bash
./fd tool rest
```

道具の収納姿勢へ動かし、トルクを切り、そのあと 1.5 秒間、腕が沈まないかを見ます。収納姿勢は、肩と肘を通常の収納と同じに
畳み、手首だけ起こして道具の先端を机の 5 cm 上に保つ姿勢です。

| オプション | 既定 | 意味 |
|---|---|---|
| `--clearance M` | 0.05 | 収納姿勢での先端の高さ（m。0.03〜0.15） |
| `--pan 度` | 20 | 収納姿勢の台座の向き |
| `--keep-torque` | — | 畳むだけで、トルクは切らない |
| `--dry` | — | 経路の確認だけ |

返ってくるもの: `torque`（`off`）、`tip_height_mm`（先端の高さ）、`sag_after_release_mm`（トルクを切ったあと沈んだ量）、
`moved`、`say`（シミュレーションでの例:「ツール「pen」を付けたまま収納しました（トルクOFF）。ツール先端は机の 50 mm 上です。」）。
11/11 に手で見つけて実際に保てた姿勢は、手首 42°・先端 56 mm でした。このコマンドが計算する姿勢は手首 44°・先端 50 mm で、
実機では試していません。

#### `fd tool detach`（登録を外す）

```bash
./fd tool detach      # ペンを実際に外してから
```

道具のファイルを消すだけです。グリッパーと `park` のロックが解け、「先端」は指先に戻ります。ハーネスは、道具が本当に
外れたかを確かめられません。返ってくるもの: `removed`、`say`。

#### `fd snap --exposure paper`（紙用の露出で撮る）

```bash
./fd snap --exposure paper
```

ふだんの固定露出（露出 333・ゲイン 29）は暗い机に合わせてあり、白い紙は白飛びして細い線が写りません。`--exposure paper`
（露出 110・ゲイン 0）は紙用の短い露出で、撮り終わると机用の値に戻します。返ってくるもの（これまでの項目に加えて）:
`exposure`、`clipped`（机の範囲のうち白飛びした割合）、`ink_visible`（この写真に細い線が写り得るか）、`paper`（紙の明るさ
`level` と理由）。白飛びした写真では `ink_visible: false` になり、`say` が「紙が白飛びしていて線は写りません。…」と言います。

11/11 の保存写真で測った値: 紙用の露出では `clipped` 0.0・紙の明るさ 155〜168・`ink_visible: true`。机用の露出では
`clipped` 0.92・`ink_visible: false`。`--frame 画像` を付けると保存画像を読み、カメラを開きません（`--sim` を付けても、
`--frame` がなければ実カメラで撮ります）。

#### `fd track-test`（空中で追従を測る）

```bash
./fd track-test          # 直径 20 mm の円を、机の 3 cm 上で、6 mm/秒でなぞる
```

| オプション | 既定 | 意味 |
|---|---|---|
| `--shape circle\|square\|line` | `circle` | 図形 |
| `--size MM` | 20 | 直径／一辺／長さ（5〜80） |
| `--v MM_S` | 6 | 先端の速さ（mm/秒。1〜30） |
| `--height M` | 0.03 | 机からの高さ（m）。**0.02 未満は断ります**（紙に触れないテストです） |
| `--at x,y` | 0.22,0.0 | 図形の中心 |
| `--pitch P` | 道具の傾き | グリッパーの傾き（道具がなければ 75） |
| `--fine` | — | ふだんの動きと「ファインモード」を交互に飛ばして比べる |
| `--repeat N` | 1 | 1 つの動き方あたりの回数（1〜5）。1 回ごとに約 20 % ばらつくので、比べるなら 3 |
| `--accept` | — | 実機で `--fine --repeat 3` と一緒に: 合格した比較を `config.json` に記録する（`--sim` では記録しません） |
| `--phys` | — | `--sim` 専用: 11/11 の記録に合わせた「引っかかっては飛ぶ」関節のモデルで飛ばす |
| `--save` / `--dry` | — | 記録を残す（実機ではいつも残します）／計画だけ |

待機姿勢へ行ってから図形をなぞり、待機姿勢に戻ります（トルク ON のまま）。返ってくるもの: `runs.default` の
`path_err_mm`（計画した線からのずれ。mean / p95 / max）、`z_err_mm`（高さのふらつき。min / max）、`lag_s`（遅れ）、
`breakdown`（ずれの内訳: 進む向き・横・高さ、関節ごと、引っかかりの様子）、`traces`（記録ファイル）、`say`。

11/11 の実測（手作りの同じ測り方、6 mm/秒）: ずれは平均 0.6〜0.8 mm・最大 2.5〜3.6 mm、高さは −3.9〜+2.5 mm ふらつき
ました。シミュレーションの理想的なサーボでは平均 0.1 mm になりますが、これは実機の見込みではありません。

**ファインモード**は、関節が向きを変えるときの「引っかかり」を先回りして押す、ゆっくりした動き専用の動かし方です。
既定では使いません。実機で `./fd track-test --fine --repeat 3 --accept` が 2 回合格して記録されると、それ以後の
`fd draw` と校正の線に自動で使われます（結果の `plan.fine_mode` が `true`）。記録を取り消すには
`./fd config --set 'fine_motion.accepted=[]'`。実機では一度も試していません（引っかかりを入れたシミュレーションで、
ずれの平均が約 1 割小さくなった程度です）。

#### `fd draw`（描く）

```bash
./fd draw cat --dry      # 配置・計画・プレビュー画像だけ
./fd draw cat            # 描く
```

1 回の呼び出しで次を順に行い、どこかで確認に落ちたら、ペンを持ち上げてそこで止まります。

| 順 | 内容 |
|---|---|
| 1 | 道具の確認。接触高さと位置補正が測ってあること（なければ `tool` で止まり、`next` が実行するコマンドを言う） |
| 2 | 腕を紙の横へどけて、紙用の露出で写真。線を写せない写真なら `visual` で止まる |
| 3 | 配置。写真に写った紙の上で、ペンが届き（下ろせて、そこから真上に 3.8 cm 上げられる）、古い線にかからない場所に枠を置く。紙の輪郭が見つかれば、その傾きに合わせる |
| 4 | 計画とプレビュー画像（写真に、枠と予定の線を重ねた物）。全部の経路を先に検査する |
| 5 | 描く。線 1 本ごとに、上で静止 → 下ろす → 線を引く（鋭い角ではいったん止まる）→ 上げる |
| 6 | 腕を紙の横へどけて写真。予定の線のうち、何 % にインクがあるかを測る |

| オプション | 既定 | 意味 |
|---|---|---|
| `--dry` | — | 上の 4 まで。何も動かない（写真は、腕が今ある場所のまま撮る） |
| `--size MM` | 105 | 枠の長い辺（mm。30〜200）。入らなければ小さくして描き、`layout.note` に理由を書く |
| `--at x,y` | 紙のうちペンが届く範囲の真ん中 | 枠の中心（机の座標、m） |
| `--rot 度\|auto` | `auto` | 枠の回転。`auto` は紙の傾きに合わせる |
| `--strokes as-is\|away\|toward\|auto` | `auto` | 線を引く向き（下の「線の向き」） |
| `--press MM` | 2.3 | 接触高さより何 mm 下を狙うか（0〜4。4 を超える値は断る） |
| `--v MM_S` | 6 | 線を引く速さ（mm/秒。1〜30） |
| `--end aside\|rest` | `aside` | 終わったあと。`aside`: 紙の横で待機（トルク ON）。`rest`: 道具の収納姿勢（トルク OFF） |
| `--min-coverage F` | 0.85 | `ok` にするのに必要な、写真で確認できた線の割合 |
| `--truth FILE` / `--new-sheet` | — | シミュレーション専用 |

絵のファイルは `{"box_mm": [幅, 高さ], "strokes": [[[u, v], …], …]}` です（mm。原点は枠の中心、u は右、v は上＝カメラから
見た向き）。名前だけ書くと `tools/draw/drawings/` の中を探します。付属は `cat`（11/11 の猫、18 画）だけです。

返ってくるもの: `layout`（枠の中心 `centre`、大きさ `size_mm`、回転、紙の輪郭が見つかったか、古い線の数）、`plan`（線の
本数 `pieces`、線の長さ、向きの決め方 `strokes` / `strokes_source`、押し込み、予定の高さ `plan_z_mm`、見込み時間）、
`preview`（プレビュー画像）、`drawn`（描けた本数と、失敗した線）、`tracking`（描いている間の追従のずれ）、`coverage`
（`drawn_fraction`: 写真で確認できた線の割合、`offset_mm`: 線のずれ、`gaps`: 欠けた所）、`pen`、`photos`、`notes`、`say`。

- **`ok` は最後の写真で決まります**: 線の 85 % 以上が確認でき、失敗した線がないこと。`gaps` に載るのは 1.5 mm 以上の
  欠けだけです（割合には短い欠けも入ります）。参考: 11/11 の手作りの猫を保存写真で同じように測ると 0.92 です。
- 線を引いている途中で動作が止まったら、まずペンを持ち上げ、次の線へ進みます。3 本失敗したら中止します（`draw`）。
- **枠は、入らなければ断らずに小さくします**（最小は 30 mm 四方）。本番は自分の写真で配置し直すので、`--dry` のあと紙や物を
  動かさないでください。結果の `layout.size_mm` と `layout.note` を見てください。
- **校正した範囲の外にも配置することがあります。** 校正で測った範囲は道具のファイルに `region` として残りますが、
  `fd draw` はそれを見ません。古い線を避けて枠が端へ寄ると、接触高さと位置補正を範囲の外まで延ばして使います
  （シミュレーション: 使い終わった紙の端に描かせると、線のずれの平均が 0.3 mm から 1.0 mm に増えました）。
  `layout.centre` が校正のときの `box.centre` から離れているときは、新しい紙にしてください。
- シミュレーション（11/11 の夜に似せた誤差を隠した世界）では、猫は 18 本・約 225 秒で、線の 99.9 % が確認でき、ずれは
  平均 0.32 mm でした。**実機の成績ではありません。**

**線の向き。** 決まりはありません。11/11 の夜は「ペン先が向いている方へ押すと線が途切れる」と考え、引く向きだけで描く
案を作りました。写真を測り直すと逆でした。ペン先はロボットから遠ざかる向きに傾いていて、線の欠けは、遠ざかる向き
（押す）が 4.5 %、横が 7.5 %、ロボットへ近づく向き（引く）が 11.7 % です。ただし絵 1 枚・ペン 1 本のデータで、欠けは
ロボットから見て右側の遠い所に集まっているので、「押す方がよい」という決まりにもしていません。向きは校正で測ります。

| `--strokes` | 意味 |
|---|---|
| `auto`（既定） | 校正の `direction` の結果に従う。差がはっきりしていれば、その向きに。差がない・測っていないときは `as-is` と同じで、結果の `notes` に「向きは測定から選んでいない」と書く |
| `as-is` | 絵のファイルにある向きのまま描く（猫は 18 本） |
| `away` | 線を切り分けて、どの線もロボットから遠ざかる向き（か横向き）に引く。近づく向きへは 6 mm までしか進まない（猫は約 34 本になり、空中の移動が増える） |
| `toward` | その逆。どの線もロボットへ近づく向き（か横向き）に引く |

### 止まったとき

`ok: false` のときは `stage` と `next` を見ます。**動いたあとで止まったときは、どの場合もペンを持ち上げてあり、結果の
`pen` に高さとアームの状態が入っています**（`tool` / `options` で断ったときは何も動いておらず、`pen` はありません）。

| `stage` | 意味 | すること |
|---|---|---|
| `tool` | 道具が未登録／未校正 | `next` のコマンド（`fd tool attach …` / `fd tool calibrate`） |
| `options` / `load` | オプションの値が範囲の外／絵のファイルが読めない | 直してやり直す。何も動いていない |
| `visual` | 写真で線の有無を判定できない（白飛び・暗い・ノイズ・腕や物が紙にかかっている・古い線の上） | **深くはしていません。** `fd snap --exposure paper` で 1 枚見て、照明や紙の上の物を直し、同じ段階をやり直す |
| `layout` | 未使用の紙・描く場所が足りない | 新しい紙にする／`--size` を小さく／捨てる紙なら `--marks-on scrap` |
| `plan` | 届かない・安全検査で断られた（何も書いていない） | `--size` を小さく／`--at x,y` で場所を変える |
| `tip` `contact` `map` `direction` | その段階の測定が成立しない | `reason` を読む。ペンが書けるか、紙が浮いていないかを見てから、その段階をやり直す |
| `draw` | 描いている途中で 3 本失敗して中止 | 最後の写真と `drawn.failed` を見る |
| `verify` | 描き終えたが、線が足りない／失敗した線がある | `coverage.gaps` と最後の写真を見る。ペンが届いていない所があれば `fd tool calibrate --stage contact` |
| `start` / `photo` | 最初の写真のために紙の横へ動く途中で止まった | `reason` と `./fd state` を見る |

`pen.where` の意味: `aside` 紙の横の待機姿勢（トルク ON）／`rest` 道具の収納姿勢（トルク OFF）／`lifted` 持ち上げたが
紙の横へは行けなかった（トルク ON）／`stopped` **持ち上げに失敗した**（その場でトルク ON。`pen.lift_error` に理由）／
`limp` トルク OFF（収納姿勢とは限らない。`./fd state` で確かめる）／`not moved` 動かしていない。

描き終えたのに `visual` になることがあります（最後の写真で線を数えられなかった場合）。絵は紙の上にあるので、写真を
見てください。シミュレーションでは、使い終わった紙の端の 38 mm の枠に猫を描かせたときにこうなりました（線が込み合うと、
紙のノイズが多い写真と区別できません）。

### 下ろし方の決まり（見えないときは止まる）

ペンを紙に下ろすのは `fd tool calibrate` と `fd draw` だけで、どちらも次の決まりに従います。深さの上限はコードの中に
固定してあり、オプションでは厳しくしかできません。

1. **線があるかないかは、写真で確かめる。** 答えは 3 通りです:「ある」「ない」「分からない」。「ない」と言えるのは、
   その写真がその場所の細い線を写せるとき（白飛びしていない・暗すぎない・紙が腕や物に隠れていない・ノイズが少ない）
   だけです。写せない写真では「分からない」と答えます。
2. **下ろす前に、その場所を写真が写せるかを確かめる。** 写せなければ、何も書かずに止まります（`visual`）。
3. **接触高さは「はしご」で探す。** 6 mm の短い線を 4 本、1 本ごとに 1.5 mm 低くして書き、紙の横へどいて写真を撮ります。
   **「4 本とも線がない」と写真がはっきり言えたときだけ**、次の 4 本をさらに下で書きます。はしごは毎回、撮り直した
   写真で確かめた未使用の紙に書きます。
4. **1 本でも「分からない」があれば止まる**（`visual`）。それ以上は書かず、深くもしません。
5. **探す深さには限りがある。** 初めて探すときは、紙があるはずの高さ（机の高さ）の 12 mm 上から 6 mm 下まで。一度
   インクが見えたあとは、その高さの 3 mm 上から 3 mm 下まで。一番上の線でもうインクが出たときは、次は上を探します
   （深くしません）。
6. **押し込む深さにも限りがある。** 校正の印は接触高さの 3 mm 下、描くときは `--press`（既定 2.3 mm、最大 4 mm）下までです
   （向きテストの線は、描くときと同じ深さ。3 mm 下を超えません）。
7. **止まるときは、まずペンを持ち上げ、どこにあるかを報告する**（結果の `pen`）。持ち上げに失敗したときは、隠さずそう
   書きます（`pen.where: "stopped"`）。

知っておくこと:

- 写真を見るのは、はしご 1 本（線 4 本）を書き終えたあとです。途中では見ません。最初にインクが出た線のあと、同じ
  はしごの残りの線（最大 3 本 ＝ 4.5 mm）は、さらに深く押します。
- 「紙があるはずの高さ」は、登録した道具の長さから計算した高さです。長さの登録が 1 cm 以上違うと、この決まりの前提が
  崩れます（`fd tool attach` の項）。最初のはしごの 1 本目が空中にあるかを、必ず目で見てください。
- 一番下の線にだけ、かすかな跡が見えたときは、そこを「触れ始めた高さ」として探索を終えます（深くしません）。写真の
  ノイズが多いときはこの扱いをせず、`visual` で止まります。
- 手動でペンを押し付ける方法は用意していません（道具が付いている間、`fd tip … --contact` は断ります）。

### 道具のファイルに残るもの

実機の道具は `tool_active.json`（プロジェクトのフォルダ直下）に 1 個だけ入ります。中身:

| 項目 | 中身 | いつ書くか |
|---|---|---|
| `name` `mount` `pitch_deg` `notes` `attached_at` | 名前、留め方、作業するときの傾き、メモ、登録した時刻 | `attach` / `set` |
| `tip_offset` | 道具の先端の位置（グリッパーの座標、m） | `attach` / `set`。校正の `tip` がインクから直す |
| `gripper_raw` | 登録したときのグリッパーの位置（以後、指令しない） | `attach` |
| `contact` | 接触高さの平面（中心、そこでの高さ、傾き、ばらつき `rms_mm`、測った点） | 校正の `contact` |
| `corr_map` | 位置補正の式（狙った場所 → 実際にインクが付く場所。係数、ずれ `rms_mm` / `max_mm`、印の数） | 校正の `map` |
| `region` | 接触高さを測った点と、そのときの枠を囲む範囲（記録だけ。`fd draw` は見ません） | 校正の `contact` |
| `calibrated` | 段階ごとの記録。いつ測ったか（`at`）と品質の数値。`tip`: 直した量と、直す前の値。`map`: インクが出なかった印の数。`direction`: 向き（`prefer`: `away` / `toward` / `any`）と向きごとの欠け | 各段階 |

ペンを付け直したら、中身は全部あてになりません。`fd tool attach --replace …` からやり直してください。ファイルが壊れて
読めないときは「道具なし」とは扱わず、動作を断ります（何が付いているか分からないまま、グリッパーを動かさないため）。

### シミュレーションでの予行（`--sim` と `--truth`）

実機に触れずに、朝の手順をそのまま試せます。

```bash
echo '{"night": true, "seed": 3}' > /tmp/night.json      # 11/11 の夜に似せた誤差を隠した世界
./fd --sim tool attach --name pen --along-fingers 0.055
./fd --sim tool calibrate --truth /tmp/night.json
./fd --sim draw cat
./fd --sim tool rest
./fd --sim tool detach
```

- `--sim` を付けた `tool …`、`track-test`、`draw` は、腕も紙もペンもカメラもシミュレーションで、実機にも実カメラにも
  触れません。**`fd --sim snap` は別です**: `--frame 画像` を付けないと実カメラで撮ります。
- `--truth FILE` は、ハーネスには教えない「本当の値」を書いた JSON です。ハーネスは、関節の角度と、あとで撮った写真しか
  見られません。

  | キー | 意味 |
  |---|---|
  | `night` | `true`: 11/11 の夜に似せた誤差一式（ペン先が登録より横に 15 mm・長さ 8 mm 違う、位置が 10 % ゆがむ、接触高さが枠の幅で 1.5 mm 傾く、高さが 1.5 mm ふらつく） |
  | `tip_error` / `true_tip_offset` | 登録値に足す先端の誤差 [x, y, z]／本当の先端の位置（m） |
  | `pos_error` `contact` `wander_mm` | 場所で変わる位置の誤差、本当の接触面、高さのふらつき（mm） |
  | `skips` | どの向きで線が途切れるか: `none`（既定）/ `tip-leading`（ペン先が先に進む向き）/ `tip-trailing`（その逆） |
  | `noise` | 写真のノイズ（既定 0.6）。0.8 までは校正が通り、1.6 以上では `visual` で止まることを確かめてあります |
  | `exposure` | `"desk"`: 全部の写真を机用の露出で撮る（白飛びして `visual` で止まる練習） |
  | `seed` `pen_width_m` `sheet` `note` | 乱数の種、線の太さ、紙の位置と傾き、メモ |

- シミュレーションの道具と紙は、ハーネスのフォルダーの外（`/tmp/tazuna_sim_<ユーザー番号>/…/`）に残り、次の `fd --sim` に
  引き継がれます: 道具（`tool_active.sim.json`）と、紙に書いた線と本当のペン先（`sim_paper.json`）。白紙に戻すには `--new-sheet`。
  `--truth` を変えるか道具を付け直すと、新しい世界になります。シミュレーションの道具がないときは、実機の道具の
  ファイルを読むだけで使います（書き換えません）。
- シミュレーションのアームは毎回、道具の収納姿勢（トルク OFF）から始まります。前のコマンドが終わった姿勢は覚えて
  いません。そのため `fd --sim draw cat --dry` の配置は、腕が紙にかかる分だけ本番と変わることがあります（試したとき:
  `--dry` は枠 90 mm、続けて実行した本番は 105 mm）。実機では、校正のあと腕は紙の横に残るので、`--dry` は本番と同じ
  配置になります。
- **シミュレーションの成功は、実機の成功ではありません。** 接触の力、インクの出方、テープの中でペンがずれること、紙が
  動くことは再現していません。確かめられるのは、手順と止まり方です。

- **手首ロールの追従誤差が最大**（40 °/s で 5.1〜5.3°、合格ライン 7°、中断 10°）。他の関節は 2.5° 以下。

  扱い、箱の中の色面積の増加も証拠にし、それでもカメラで分からないときは「元の場所にない・テーブルに落ちていない・
  爪が空」で推定確認（結果の `checks.verify.how` に `inferred` と出ます）するようにしました。

うまくいかないとき:

- 動作ループが遅い／通信エラーが出る → `./fd config --set stream_feedback=false`（v1 と同じ読み方に戻す）。
- 空中の動作が「補正の上限を超えて押している」で止まる → 摩擦が想定より大きい: `./fd config --set friction_corr_max_deg=2.5`。
- 把持の閉じ方が強すぎる／物体が弾かれる → `./fd config --set gripper.velocity_cap=500`（今は 700。上限 1100）。
- 手首ロールの追従誤差が大きい（bench の `roll_swing_90`）→ `./fd config --set joint_speed_scale.wrist_roll=1.0`。
- つかむ位置がいつも同じ向きにずれる → `./fd pick ... --visual on`（爪を見て補正）を試す。逆に補正が怪しければ `--visual off`。

空きがなければ近くの空いた所へ移ります。位置補正ができる前は、インクが狙いから 2 cm 近くずれて付くことがあります。
シミュレーションは A4 の紙で通しています。紙が足りないと `layout` で止まります。

余力があれば（描いたあとで）: `./fd track-test --fine --repeat 3`（円を 6 回、約 2 分）で、ふだんの動きとファインモードを
比べられます。`--accept` を付けると合格を記録し、2 回記録されると以後の描画がファインモードになります。初回の描画は
記録する前に（昨夜と同じ動かし方で）行ってください。

うまくいかないとき（道具と描画）:

- `tip` が「no ink down to …」で止まる → ペンが書けるか（キャップ、インク）を見る。登録した長さが実際より長いと紙に
  届きません: `./fd tool set --along-fingers <短い値>` のあと、もう一度。
- 一番上の線からインクが出る → コマンドは自分で上を探し直します。2 回上げてもまだ出るときは「登録より道具がずっと長い」
  で止まります: 長さを測り直してください。
- `contact` が「do not lie on a plane」→ 紙が浮いているか、高さのふらつきが大きい。紙を貼り直してやり直す。
- 線が片側だけ薄い・途切れる → 昨夜も、左右で接触高さが約 0.8 mm 違いました。`./fd tool calibrate --stage contact` を
  やり直すか、`--press 3`（最大 4）で描く。
- 途中で紙を替えた → 接触高さと位置補正はロボットの座標で持っているので、同じ場所・同じ厚さの紙ならそのまま描けます。
  心配なら `--stage contact` から。

## 7. 安全のための設計

- **サーボの校正（EEPROM）には書き込みません**。位置は生の目盛りで扱い、座標変換は `config.json` の `zero_ticks` で行います。
  LeRobot の校正プロンプト（"use file"）は受けないでください（`my_follower_arm.json` はこのアームの実校正と一致しません）。
- 位置ゲイン P は動作中だけ 32（RAM のみ）にし、トルク OFF で 16 に戻します。
- 動作前に必ず検査: 関節限界・床（テーブル面）・立入禁止領域（台座、ケーブル、カメラが見た他の物体）・速度・サーボ状態。
- 動作中: 追従誤差・サーボの異常ビット（過負荷・過熱・過電流）・電圧を毎周期見て、異常なら押し付けを解放して停止。
- 行き先が塞がれていたら（テーブルや物に当たったら）押し続けず、解放して `MotionAborted` を返します。
- 箱の中へ降りるとき（`take`）: 立入禁止領域は指先の 1 点で判定するため、箱とその中身については無効にせざるを
  得ません。代わりに、爪の輪郭（厚み・幅）と箱の壁・隣の物との空きを `takeout.py` が計画段階で検査し、降下は
  その位置での垂直線だけにします。爪の位置をカメラで測れなければ降りません（この目視は設定で切れません:
  実機で `take.visual` が `on` 以外なら `take` は動かずに断ります。測れる範囲の限界は 1 章）。
- 収納（`park`）と、箱が腕の陰のときの見直しのための畳み込みは、**机の上の物を知らずに**収納姿勢へ下ろします
  （固定の立入禁止領域だけを見て、接触を許して動く）。そのため `take` は、収納姿勢で爪が下りる場所から 4 cm 以内
  には物を置かず（`--to` で指定しても断る）、最初の 1 枚でそこに物が見えたら畳みません。`fd park` 自体はカメラを
  見ないので、ロボット正面の収納位置（爪先は x 約 0.18 m、y 約 0.01 m）に物があるときは、どけてから park してください。
- 保存画像（`--frame`）で実機を動かすことはできません。`pick` / `take` / `do` / `repl` に `--frame` を付けるなら
  `--sim` か `--dry` が必要で、どちらもなければカメラも通信も開く前に `SafetyError` で断ります。
- 依頼文（`fd do`）は、素直な肯定の命令文と読めたときだけ実行します。禁止・除外・条件・質問などを含む文は、
  物と箱の名前が読めても動かしません（2 章）。
- 失敗時の方針: **何も持っていなければ待機姿勢へ退避**、**物を持っている／動作異常のときはその場で停止して保持**
  （勝手に動かない）。結果の `arm_state` と `next` に従ってください。
- `torque off` は腕が持ち上がっていると拒否します（落下防止）。終了は `park`。
- **道具（ペン）が登録されている間**（4 章。実機では未検証）: グリッパーには指令を出しません。`pick` / `take` / `do` /
  `repl` / `grip` / `grasp` / `probe` / `bench` / `park` / `calib-at` / `servo-tip` と、`tip` / `joints` の `--contact` は、
  動く前に断ります。空中の移動は、道具の先端が机の 2 cm より下に来ない経路だけを通ります。`torque off` は道具の収納姿勢の
  ときだけ通ります（`--force` は、人が腕を支えているときの非常用）。終了は `fd tool rest`。道具のファイルが壊れて読めない
  ときは「道具なし」とは扱わず、動作を断ります。**登録していない道具は、ハーネスには見えません**: ペンを付けたら
  `fd tool attach`、外してから `fd tool detach`。
- **ペンを紙に下ろすのは `fd tool calibrate` と `fd draw` だけ**で、どちらも「見えないときは止まる」決まり（4 章）に従い
  ます。写真が線を写せないときは下ろしません。深くするのは、「線がない」と写真が言えたときだけです。深さの上限は固定で
  （探すときは紙があるはずの高さの 6 mm 下まで、インクが見えたあとはその 3 mm 下まで、描くときは接触高さの 4 mm 下まで）、
  止まるときはペンを上げて場所を報告します。この上限は「登録した道具の長さがおよそ合っている」ことが前提です。
- 未検証の速度段は使えません。シミュレーションでの合格は実機の検証として記録されません。ファインモード（4 章）も同じで、
  実機の `fd track-test --fine --repeat 3 --accept` が 2 回合格して記録されるまで、描画には使われません。

    （15 mm 短い登録で紙の面の 7 mm 下、22 mm 短い登録で 14 mm 下まで押す指令になりました）。長さは 5 mm 以内で測り、
    最初のはしごの 1 本目が空中にあるかを見てください（5 章）。
  - 写真を見るのは、はしご 1 本（線 4 本）ごとです。最初にインクが出た線のあと、同じはしごの中で最大 4.5 mm 深くなります。
  - `fd draw` は、校正した範囲（道具のファイルの `region`）を見ません。古い線を避けて枠が端へ寄ると、接触高さと
    位置補正を範囲の外まで延ばして使います。`layout.centre` を確かめてください。
  - `fd tool calibrate --start-above` は 30 まで受け付けますが、25 を超えると、はしご 5 本では紙まで届かないことが
    あります。そのときも理由は「紙があるはずの高さの 6 mm 下まで探した」と出ます（実際はそこまで下りていません。
    結果の `pen.lowest_plan_z_mm` が本当に下りた高さです）。
  - Ctrl-C や打ち切り（SIGTERM。Bash の timeout など）で止めると、ペンを真上へ持ち上げてから結果の JSON を返します
    （`ok: false`, `interrupted: true`。11/12 朝に修正、シミュレーションで確認）。`kill -9` だけは別で、アームは
    その場で保持します（ペンが紙に付いたままのことがあります）。どちらの場合も `./fd tool rest` が先に真上へ
    持ち上げてから収納します。**校正は約 5〜6 分、描画は約 4〜5 分かかるので、呼ぶ側の timeout は 600 秒にしてください。**
  - 道具の先端や角度を `fd tool set` で変えたあと、前の校正（接触高さ・位置補正）は使えません。`fd draw` は `tool` の
    段階で断り、`fd tool calibrate` のやり直しを求めます（11/12 朝に修正。校正に、測ったときの先端と角度を残す
    ようにしました。その記録が無い古い校正も「やり直し」と判定します）。
  - **未修正: `fd tool calibrate --dry` は、紙の空きが足りなくても「計画ができました」と答えることがあります。** 予行は
    紙の空きを最初の段階（先端の試し線）についてしか見ていません。本番では試し線を書いたあと、接触高さの段階で
    「場所が無い」と止まります（ペンは持ち上げてあります）。校正は新しい紙で始めてください。
  - **未修正: `fd draw` の `--at` と `--size` は「希望」として扱われます。** 入らない・古い線に重なるときは、断らずに
    別の場所・小さい寸法で描きます。結果の `layout`（`centre`, `size_mm`）に実際の値が出るので、`--dry` で必ず
    確かめてください。
  - 描く線の総延長に上限はありません（猫は 862 mm、約 4 分）。長い絵は呼ぶ側の timeout を超えます。
  - 予想時間（`expected_s`）は実際（シミュレーション）より 17〜48 % 長めに出ます。
  - `fd tool rest` はカメラを自動露出に戻しません（`./fd camera auto` で戻します）。
  - 小さな枠に線の多い絵を描くと、最後の確認が線を数えられず `visual` になることがあります（絵は描けています）。
  - シミュレーションのアームは毎回、収納姿勢から始まるので、`fd --sim … --dry` の配置は本番と違うことがあります。
  - `strokes.py` / `tooling.py` / `simpaper.py` のコメントと `tests/testdata/pen_20261111/manifest.json` の説明文には、誤りと
    分かった「押す向きは線が途切れる」という文が残っています。動作は測定に従います（4 章）。
  - シミュレーションは、接触の力、インクの出方、テープの中でのペンのずれ、紙の動きを再現しません。
- **道具と描画の検証状況（11/12 朝）**: 作ったあとの独立した検証は 3 本の予定のうち「使い勝手」1 本だけが完了しました。
  「安全」と「見え方・校正」の検証、およびその後の修正担当は、利用上限に達して実行できていません。使い勝手の検証で
  出た重要な指摘 5 件のうち 3 件（道具が未登録のまま動かす危険の注意書き、中断時にペンを上げる、古い校正を断る）は
  直し、2 件（上の「未修正」）は残っています。安全と校正の読み取りは、作った担当のテストと統合テストだけが根拠です。
- 対応している作業は「テーブルの上の物を箱に入れる」（`pick`）、「箱の中の物を取り出して机に置く」（`take`、実機未検証）、
  「ペンで線画を描く」（`draw`、実機未検証）です。積む・並べる・箱から箱へ移す等は低レベルコマンドで LLM が組み立てる
  必要があります（遅い。2 章の「定型外の作業」を参照）。

## 10. ファイル構成

2026-11-13 に、機能ごとのフォルダへ分けました。ロボットの動かし方は同じで、置き場所が変わりました。あわせて、次の点を
変えています。

- `fd` が使う Python の選び方（「はじめに」）。Python やパッケージが見つからないときは、JSON のエラーを 1 個返します。
- 実機のアームを開く条件: `config/config.json` が無いとき、関節の原点・指先の位置・机の高さが入っていないとき、整理より前の
  置き場所（プロジェクトのフォルダ直下）に設定や校正のファイルが残っているときは、開きません。
- `--sim` を付けたとき、設定や校正を書き換えるコマンド（`config --set`、`calib-fit`、`calib-roll`、`table-fit`、`ref`）と
  `camera` は断ります（それまでは、`--sim` を付けても装置のファイルを書き換えていました）。`config --set` は、設定ファイルが
  無いときに新しく作りません。`table-fit` は、`--force` を付けたときだけ保存します（入力の高さが 3〜18 mm 深く出るため）。
- 運動学の計算を `tools/ik/` に集めました（中身は変えていません）。

**整理より前の構成から更新するとき**（2026-11-13 より前に取り出した作業フォルダ）は、更新したあとに次のことをします。

1. `config/python` に、その PC で使う Python のパスを 1 行書きます（以前は起動スクリプトに書いてありました）。
2. `ref_table.jpg` を `config/` へ移します（移さないと、`calib-at` と `servo-tip` は基準の写真なしで指先を探し、結果の
   `reference_photo` が `false` になります）。自分で測った `config.json`・`camera_model.json`・`calib_points.json`・`probes.json` が
   フォルダ直下に残っていれば、それも `config/` へ移します（残っている間、実機のアームは開きません）。
3. 道具のファイル `tool_active.json` は、プロジェクトのフォルダ直下のままです（`config/` へは移しません）。
4. 自分で置いたフック（`.git/hooks/pre-commit`）があれば、`tools/privacy_wipe.py` を `tools/publish/privacy_wipe.py` に直します。

**道具の登録は、フォルダごとです。** 同じ PC にこのリポジトリのコピーがほかにあっても（取り出し直したもの、作業用の写し）、
そのコピーは、いまグリッパーに付いている道具を知りません。実機を動かすコマンドは、道具を登録したフォルダの `fd` だけから
実行してください。ほかのコピーで試すときは、必ず `--sim` を付けます。

GitHub の公開リポジトリ（https://github.com/FaBoAI/Tazuna）に入れているのは、コード・文書・設定・テスト用のデータと、アイコンの画像 2 枚だけです。
実行ログと写真（`runs/`）、設定とコードの履歴（`backups/`）、動画の素材（`video/`）、いまグリッパーに付いている道具のファイル
（`tool_active.json`）、その PC でどの Python を使うか（`config/python`）、レビューと調査の記録は、ロボット側の PC にだけ
あります（何を入れるかは `.gitignore` に書いてあります）。写真は、テストが使う 65 枚だけを入れています（テストが使わない写真、
`fd ref` が撮り直す `config/ref_table.jpg`、テストが書き出す画像は入れていません。正解データ `manifest.json` には、入れていない
写真の名前も記録として残っています）。
そのうち 42 枚は、人が写っていた部分を灰色に塗りつぶしてあります（`tools/publish/privacy_wipe.py`）。塗った範囲に接する
1 画素を除いて、範囲の外の画素は元の写真と同じです。入れた写真は、AI が縮小した一覧と拡大した切り抜きで確認し、別の AI による
レビューでも確認しました（人の目による全数確認はしていません）。確認したときの内容は `tests/testdata/reviewed_photos.json`
（パスと SHA-256）に記録しています。
