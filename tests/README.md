# tests — 実機を使わないテスト

TAZUNA のテストは、シミュレーションのアーム、疑似サーボ、保存した写真だけで動きます。実機と実カメラには触れません（実カメラを開くのは `python tests/test_scene.py --live` と指定したときだけです）。シミュレーションでの合格は、実機で動くことの確認ではありません。道具（グリッパーに留めたペン、筆）、描画、絵の具、空中校正のテストの合格は、「手順と止まり方、サーボへ送る指令が、決めたとおり」という意味です（[docs/MANUAL.md](../docs/MANUAL.md) 8 章）。絵の具、紙、筆のしなり、爪のガタ、カメラについては、何も言いません。

## 実行のしかた

```bash
python tests/run_all.py            # 全部。20 本を 1 本ずつ別のプロセスで実行します（Jetson Orin Nano で約 35 分）
python tests/run_all.py ink tool   # ファイル名にその語を含むものだけ（この例は test_ink.py、test_tooling.py、test_tooljaw.py）
python tests/run_all.py paint      # test_paint_model.py と test_paint.py
python tests/test_ink.py           # 1 本だけ
python tests/test_paint.py contact # 2026-11-13 に加えた 6 本は、名前にその語を含むテストだけを実行できます
```

- テストは、`fd` と同じ Python で動きます（環境変数 `TAZUNA_PYTHON`、なければ `config/python` に書いたパス、どちらもなければ `run_all.py` を起動した Python）。その Python に numpy、OpenCV、feetech-servo-sdk、pyserial が必要です。1 本だけ実行するときは、その Python で起動してください。確かめた組み合わせは、Python 3.13 + numpy 2.5 + OpenCV 4.13（全部）と、Python 3.12 + numpy 1.26 + OpenCV 4.8（短い 4 本: nlq、ink、sim、skills）です。
- `run_all.py` は、最初に使う Python を 1 行表示し、そのあと 1 本ごとに 1 行（`ok` か `FAIL`、スイートの名前、秒数、最後の出力行）を表示します。全部合格すると、最後に `all suites passed` と出ます。語で絞ったときは `the N selected suite(s) passed`、どのスイートにも当たらないときは何も実行せずにそう表示します。
- どのスイートも、装置のファイルを書きません。道具、設定、カメラモデル、絵のセットアップと状態、写真のフォルダ、実行ログ、実機のロックは、環境変数でテスト用の場所に差し替えます（`$FD_TOOL`、`$FD_CONFIG`、`$FD_CAMERA_MODEL`、`$FD_PAINT_SETUP`、`$FD_PAINT_STATE`、`$FD_PAINT_OUT`、`$FD_RUNS`、`$TAZUNA_HW_LOCK`）。道具と描画の 6 本と、2026-11-13 に加えた 6 本には、サーボのポート、カメラ、`v4l2-ctl` に触れようとすると失敗にする監視を入れてあります。2026-11-13 に加えた 6 本は、最後のテスト（`test_zz_…`）が、装置のファイルと実行ログが変わっていないことを確かめます。
- **実機がロックされている間（`fd hw lock`）も、テストは動きます**（2026-11-14 未明に修正。それまでは、ロック中に `test_ink.py` の 4 件と `test_scene.py` の 2 件が、カメラの代役に届く前にロックで断られていました）。`test_ink.py` は、自分用のロックのファイルを使います（このスイートのカメラは、記録するだけの代役です）。`test_scene.py` は、カメラの代役を使う 2 件の間だけ、ロックの代役を立てます。`python tests/test_scene.py --live` は、ユーザーのロックを守ったままです（ロック中は実カメラを開きません）。どちらのスイートにも、代役でないカメラやサーボのポートを開こうとすると失敗にする監視と、ユーザーのロックのファイルが変わっていないことを確かめるテストを足してあります。2026-11-13 に加えた 6 本は、自分用のロックのファイルを使うので、ロック中でも合格します。

## `refs/` — 照らし合わせる資料

`refs/urdf/` は SO-101 の URDF・MJCF・メッシュ（STL）で、[TheRobotStudio/SO-ARM100](https://github.com/TheRobotStudio/SO-ARM100) から取ったものです。出どころ（フォルダ、コミット、ライセンス）は、リポジトリのルートの [NOTICE](../NOTICE) に書いてあります。`refs/gripper/` は、同じメッシュから測ったグリッパー形状の参照実装です。テストはこの 2 つを、運動学とグリッパー形状の独立した基準として使います。
